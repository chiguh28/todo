## 2. システム概要

TaskFlow は、小規模チーム（3〜5 名）を対象とした**ローカル動作型のタスク管理アプリケーション**である。タスクの一覧管理とガントチャートによる視覚的な進捗管理を統合し、外部サービスへの依存なしにチーム全員のタスクを一元管理できる。

### 技術スタック概要

| レイヤー | 技術 |
|----------|------|
| バックエンド | Python / Flask（アプリファクトリパターン） |
| フロントエンド | React 18 + Babel Standalone（ビルドステップなし） |
| データベース | SQLite（WAL モード、外部キー制約有効） |
| 通信 | REST API（JSON） |
| 実行環境 | ローカルホスト（localhost:5000） |

---

## 3. 対象ユーザー・利用シーン

### 対象ユーザー

- 小規模チームのプロジェクトリーダーおよびメンバー（3〜5 名）
- 外部 SaaS ツールを使わずにローカル環境でタスク管理を行いたいチーム
- ガントチャートによるスケジュール可視化を必要とする担当者

### 主な利用シーン

1. **朝会・週次確認**: ガントチャートを開き、当日・当週の予定と遅延タスクを確認する
2. **タスク登録**: 新規タスクを作成し、担当者・開始日・工数・優先度を設定する
3. **進捗更新**: ガントチャート上のタスクバーをクリックし、進捗率をポップオーバーで更新する
4. **サブタスク管理**: 大きなタスクをサブタスクに分解し、個々の進捗を親タスクへ自動集約する
5. **マイルストーン確認**: ガントチャートのマイルストーンマーカーで重要な期日を把握する
6. **統計確認**: ダッシュボード拡張で KPI・Sカーブ・ワークロード分布を俯瞰する
7. **手順書作成**: タスク一覧のドキュメントアイコンをクリックし、作業手順書をリッチテキストで記述・画像付きで整備する

## 4. 機能要件

### 4.1 タスク管理

#### FR-001: タスク作成
タスクを新規作成できる。入力項目は以下のとおり。

| フィールド | 必須 | 説明 |
|-----------|------|------|
| タイトル | 必須 | タスク名（一覧・ガントチャートに表示） |
| 説明 | 任意 | 詳細説明（フリーテキスト） |
| 担当者 | 任意 | 登録済みメンバーから選択 |
| 開始日 | 必須 | タスク開始日（YYYY-MM-DD） |
| 工数 | 必須 | 作業時間（時間単位、実数） |
| 進捗率 | 任意 | 0〜100（%）、デフォルト 0 |
| 優先度 | 任意 | 低 / 中 / 高、デフォルト 中 |
| ステータス | 任意 | 未着手 / 進行中 / 完了、デフォルト 未着手 |
| カテゴリ | 任意 | 既存カテゴリ選択または新規入力 |
| マイルストーン | 任意 | フラグ設定（ガントチャートに 🚩 表示） |

#### FR-002: タスク参照
タスク一覧をテーブル形式で表示する。列には少なくともタイトル・担当者・開始日・終了日・工数・進捗率・ステータス・優先度・カテゴリを含む。

#### FR-003: タスク更新
タスクの全フィールドを編集フォームから更新できる。

#### FR-004: タスク削除
タスクを削除できる。削除時に確認ダイアログを表示する。サブタスクが存在する場合はサブタスクも連動して削除される。

#### FR-005: ステータス自動更新
進捗率を変更した際に、ステータスを以下のルールで自動設定する。

| 進捗率 | 自動設定ステータス |
|--------|--------------------|
| 0% | 未着手 |
| 1〜99% | 進行中 |
| 100% | 完了 |

#### FR-006: 終了日自動計算
終了日はデータベースに保存せず、フロントエンドで以下の計算式により算出する。

```
終了日 = 開始日 + ceil(工数 / 8) 営業日
```

営業日の定義は休日モード（FR-020）の設定に従う。

#### FR-007: ソート順管理
タスクは `sort_order` フィールドを持ち、ドラッグ等による並び替えをサポートできる構造とする（UI実装は別途定義）。

---

### 4.2 サブタスク機能

#### FR-008: サブタスク作成
既存タスクを親として、サブタスクを作成できる（`parent_id` による自己参照）。

#### FR-009: 親タスク進捗の自動計算
サブタスクの進捗率が変更された場合、親タスクの進捗率をサブタスクの平均値で自動更新する。

#### FR-010: サブタスク表示
タスク一覧で、サブタスクを親タスクの直下にインデント表示する。

---

### 4.3 カテゴリ管理

#### FR-011: カテゴリ選択・作成
タスク作成・編集フォームにて、既存のカテゴリ一覧から選択、または任意の文字列を入力して新規カテゴリを作成できる。

#### FR-012: カテゴリ別グループ表示
ガントチャートにおいて、タスクをカテゴリ別にグループ化して表示する機能を提供する。

---

### 4.4 ユーザー（メンバー）管理

#### FR-013: メンバー作成
メンバー名とカラー（HEX カラーコード）を設定してメンバーを登録できる。メンバー名は一意とする。

#### FR-014: メンバー一覧参照
登録済みのメンバーを一覧表示する。

#### FR-015: メンバー削除
メンバーを削除できる。削除時、そのメンバーが担当者として設定されているタスクの担当者フィールドを NULL（未設定）にする。

#### FR-016: デフォルトメンバー
DB 初期化時に以下の 3 名のデフォルトメンバーを自動作成する。

| 名前 | カラー |
|------|--------|
| 田中 | （システム定義色） |
| 佐藤 | （システム定義色） |
| 鈴木 | （システム定義色） |

---

### 4.5 ガントチャート

#### FR-017: 日グリッド表示
タスクの期間を日単位のグリッドで表示する。

#### FR-018: タスクバー表示
各タスクを担当者のカラーで色分けしたバーとして描画する。バーの長さは開始日〜終了日（FR-006 で計算）に対応する。

#### FR-019: 今日ライン表示
現在日付を示す縦ラインをガントチャート上に常時表示する。

#### FR-020: 進捗率ポップオーバー編集
ガントチャートのタスクバーをクリックすると、進捗率を入力できるポップオーバーを表示する。更新後は FR-005 のルールに従いステータスを自動設定する。

#### FR-021: 開始日順ソート切替
ガントチャートのタスクをデフォルトソート順 / 開始日順で切り替えられるトグルを提供する。

#### FR-022: マイルストーンマーカー表示
マイルストーンフラグが設定されたタスクに 🚩 マーカーをガントチャート上に表示する。

#### FR-023: 遅延タスクのパルスアニメーション
終了予定日が今日より前であり、かつ完了していないタスクのバーにパルスアニメーションを適用して視覚的に遅延を通知する。

#### FR-024: 担当者別自動日程ずらし
同一担当者のタスクが日程重複する場合、`shifted_start_date` を計算してガントチャート上での表示をずらす。元の開始日は変更しない。

#### FR-025: サイドバーリサイズ
ガントチャートのサイドバー（タスク名列）幅をドラッグ操作で調整できる。設定値は `localStorage` に保存し、次回起動時にも反映する。

#### FR-026: カテゴリ別グループ表示
ガントチャートをカテゴリ別にグループ化して表示するモードを提供する。

---

### 4.6 フィルター・検索

#### FR-027: テキスト検索
タスク名の部分一致によるテキスト検索を提供する。リアルタイムで一覧・ガントチャートを絞り込む。

#### FR-028: 担当者フィルター（複数選択）
1 名以上の担当者を選択してタスクを絞り込める。複数選択時は OR 条件とする。

#### FR-029: ステータスフィルター（複数選択）
1 つ以上のステータス（未着手 / 進行中 / 完了）を選択してタスクを絞り込める。複数選択時は OR 条件とする。

#### FR-030: カテゴリフィルター（複数選択）
1 つ以上のカテゴリを選択してタスクを絞り込める。複数選択時は OR 条件とする。

#### FR-031: フィルタークリア
設定中の全フィルターを一括解除する機能を提供する。

---

### 4.7 休日モード

#### FR-032: 休日モード設定
以下の 2 モードを切り替えられる。設定は `localStorage` に保存し次回起動時にも反映する。

| モード | 説明 |
|--------|------|
| 土日のみ | 土曜・日曜を非営業日として終了日を計算する |
| 土日祝 | 土曜・日曜に加えて日本の祝日（振替休日含む）を非営業日として計算する |

#### FR-033: 日本の祝日自動算出
「土日祝」モード選択時、日本の祝日（振替休日を含む）をアプリ内のロジックで自動算出する。外部 API への依存は不要とする。

---

### 4.8 拡張機能システム

#### FR-034: 拡張機能の自動読み込み
`extensions/` ディレクトリ直下に配置した Python パッケージを、アプリ起動時に自動検出・読み込む。

#### FR-035: バックエンド拡張 API
拡張機能は `TaskFlowExtension` 基底クラスを継承し、以下を実装できる。

| メソッド | 説明 |
|---------|------|
| `get_blueprint()` | Flask Blueprint の返却（None 可） |
| `init_db(db)` | `ext_` プレフィックス付き DB テーブルの初期化 |
| `get_static_files()` | 提供する JSX / CSS ファイルのリスト |

#### FR-036: フロントエンド拡張 API
拡張機能は `TaskFlow.registerExtension()` を呼び出し、以下を登録できる。

| 登録種別 | 説明 |
|---------|------|
| タブ | メインナビゲーションに独自タブを追加 |
| フォームフィールド | タスク作成・編集フォームに独自フィールドを追加 |
| 列 | タスク一覧テーブルに独自列を追加 |
| ヘッダーアクション | ヘッダーエリアに独自ボタン/コントロールを追加 |
| フック | タスクイベント（下記）に対するコールバックを登録 |

#### FR-037: タスクイベントフック
以下のイベント発火時に、登録済みコールバックを呼び出す。

| イベント | 発火タイミング |
|---------|--------------|
| `task:created` | タスク作成完了後 |
| `task:updated` | タスク更新完了後 |
| `task:deleted` | タスク削除完了後 |

#### FR-038: 拡張機能 API アクセス
拡張機能のフロントエンドコードは `TaskFlow.api` を通じて、コア機能と同一の HTTP ヘルパー（GET / POST / PUT / DELETE）を利用できる。

---

### 4.9 統計ダッシュボード（標準拡張機能）

#### FR-039: KPI カード表示
以下の KPI をカード形式で表示する。

| KPI | 説明 |
|-----|------|
| タスク完了数 | ステータスが「完了」のタスク数 |
| 平均進捗率 | 全タスクの進捗率の平均値（%） |
| 工数消化率 | 完了タスクの工数合計 / 全タスクの工数合計（%） |
| 遅延タスク数 | 終了予定日超過かつ未完了のタスク数 |

#### FR-040: Sカーブチャート表示
計画上の完了予定累積工数と実績の累積完了工数を時系列グラフ（Sカーブ）として表示する。

#### FR-041: ステータス分布ドーナツチャート
未着手 / 進行中 / 完了のタスク件数をドーナツチャートで表示する。

#### FR-042: 優先度分布ドーナツチャート
低 / 中 / 高の優先度別タスク件数をドーナツチャートで表示する。

#### FR-043: スケジュール健全性バー
遅延タスク / 正常タスクの比率をプログレスバーで視覚化する。

#### FR-044: メンバー別ワークロード表
メンバーごとの担当タスク数・合計工数・平均進捗率を表形式で表示する。

### 4.10 タスク手順書機能

#### FR-045: ドキュメントアイコン表示
タスク一覧のアクション列に、ドキュメントアイコン（📄）ボタンを表示する。

- 手順書が既に作成済みのタスクはアイコンをアクセント色で表示し、右上に青い dot バッジを付与する
- 手順書が未作成のタスクはアイコンをグレーアウト（低彩度・低透明度）で表示する

#### FR-046: ドキュメント編集モーダル表示
タスク一覧のドキュメントアイコンをクリックすると、手順書の編集モーダルを表示する。

- モーダルはオーバーレイ背景（blur 付き）の中央に表示する（幅 80vw、高さ 80vh、最大幅 1100px）
- モーダルヘッダーにタスク名・タスク番号を表示する
- モーダル内には「編集」「プレビュー」の 2 タブを設ける
- モーダルを開いた際は常に「編集」タブが選択された状態にする

#### FR-047: リッチテキストエディタ（Quill.js）
「編集」タブにリッチテキストエディタを表示する。以下のフォーマット操作をツールバーから提供する。

| 機能 | 説明 |
|------|------|
| 見出し | H1 / H2 / H3 / 本文 を切り替え |
| 太字・斜体・下線 | インラインテキスト装飾 |
| 番号付きリスト・箇条書きリスト | リスト形式の入力 |
| リンク | URL のインライン埋め込み |
| 画像挿入 | ツールバーボタンまたはフッターボタンから画像を挿入（FR-048） |
| コードブロック | ソースコード・コマンドの整形表示 |
| 書式クリア | 選択範囲の書式をリセット |

#### FR-048: 画像挿入
手順書に画像をアップロードして埋め込むことができる。

- モーダルフッターの「🖼 画像を挿入」ボタン、またはツールバーの画像ボタンをクリックするとファイルピッカーを開く
- 対応フォーマット: 一般的な画像形式（PNG・JPEG・GIF・WebP 等）
- 選択した画像はリッチテキスト内の現在のカーソル位置に埋め込む
- 埋め込み画像は最大幅 100% でリサイズし、角丸・ボーダーを付与して表示する
- 画像データは Base64 エンコードして手順書の HTML コンテンツとともに DB に保存する

#### FR-049: プレビュー表示
「プレビュー」タブに、リッチテキストエディタの内容をレンダリングした読み取り専用ビューを表示する。コンテンツが空の場合は空状態メッセージを表示する。

#### FR-050: 手順書の保存
モーダルフッターの「💾 保存」ボタンを押すと、手順書の HTML コンテンツを該当タスクに紐付けて保存する。

- 保存成功時はトースト通知を表示する
- 保存後、タスク一覧のドキュメントアイコン表示状態（有無）を更新する

#### FR-051: 手順書のデータモデル
手順書データを格納する `task_documents` テーブルをコアテーブルとして追加する。

| カラム | 型 | 説明 |
|--------|------|------|
| `task_id` | INTEGER | タスク ID（FK → tasks.id、ON DELETE CASCADE） |
| `content` | TEXT | Quill.js が出力する HTML 文字列（画像 Base64 含む） |
| `updated_at` | TEXT | 最終更新日時（ISO 8601） |

主キーは `task_id` とし、1 タスクにつき 1 件の手順書を管理する。

#### FR-052: 手順書 API
手順書の取得・保存を行う REST API エンドポイントを追加する。

| メソッド | パス | 説明 |
|--------|------|------|
| GET | `/api/tasks/<id>/document` | 指定タスクの手順書を取得。存在しない場合は `{ "content": "" }` を返す |
| PUT | `/api/tasks/<id>/document` | 指定タスクの手順書を保存（INSERT OR REPLACE） |

## 5. 非機能要件

#### NFR-001: ローカル動作
外部ネットワークへの依存なしに、ローカル環境（`localhost:5000`）で完全動作すること。React および Babel は CDN から読み込むため、初回起動時のみインターネット接続が必要。

#### NFR-002: データ永続化
SQLite データベースをアプリケーションと同一ディレクトリに配置し、アプリ再起動後もデータが維持されること。WAL モードおよび外部キー制約を有効化すること。

#### NFR-003: ビルドステップ不要
フロントエンドは React 18 + Babel Standalone を CDN 経由で読み込み、JSX のトランスパイルをブラウザ上で行う。`npm install` / `webpack` 等のビルドツールは不要とする。

#### NFR-004: 日本語 UI
すべてのユーザー向け文字列（ラベル・メッセージ・エラー・ツールチップ等）を日本語で記述する。

#### NFR-005: ライトテーマ
UI はライトテーマを基本とし、CSS カスタムプロパティ（CSS Variables）でカラースキームを管理する。ダークテーマは本バージョンのスコープ外とする。

#### NFR-006: デスクトップ前提
レスポンシブデザインは対象外とする。対象ブラウザはデスクトップ向けモダンブラウザ（Chrome / Edge 最新版）とする。

#### NFR-007: 同時利用
同一ネットワーク内の複数メンバーが同一サーバーに接続して利用できる構成を想定する。ただし、リアルタイム同期（WebSocket 等）は本バージョンのスコープ外とし、ページ更新で最新データを取得する。

#### NFR-008: 拡張機能の安全な分離
拡張機能の DB テーブルは `ext_` プレフィックスを必須とし、コアテーブルへの直接変更は禁止する。拡張機能の JSX ファイルは IIFE（即時実行関数式）でラップし、グローバルスコープの汚染を防ぐ。

#### NFR-009: 起動速度
通常の利用（タスク数 1,000 件以下）において、ページ初期ロード完了まで 3 秒以内（ローカルネットワーク環境）を目標とする。

#### NFR-010: 設定の永続化
ユーザー固有の設定（休日モード、ガントチャートサイドバー幅等）は `localStorage` に保存し、ブラウザ再起動後も維持されること。

| 用語 | 説明 |
|------|------|
| タスク | チームが管理する作業単位。タイトル・工数・担当者等の属性を持つ |
| サブタスク | 親タスクに紐づく子タスク。`parent_id` で親を参照する |
| 工数 | タスクに要する作業時間。時間単位（例: 8 時間 = 1 営業日） |
| 終了日 | 開始日と工数から算出される予定完了日。DB には保存しない |
| 営業日 | 休日モードの設定に基づき、土日（または土日祝）を除いた日 |
| 進捗率 | タスクの完了度合いを 0〜100% で表した数値 |
| マイルストーン | プロジェクト上の重要な期日を示すフラグ。ガントチャートに 🚩 表示される |
| カテゴリ | タスクを分類するためのラベル。ガントチャートでのグループ化に利用 |
| 担当者（メンバー） | タスクを担当するチームメンバー。名前とカラーコードを持つ |
| シフト開始日 | 担当者の日程重複を回避するためにシステムが算出する表示用開始日（`shifted_start_date`）。元の開始日は変更しない |
| 休日モード | 終了日計算に用いる非営業日の定義。「土日のみ」または「土日祝」を選択できる |
| WAL モード | SQLite の Write-Ahead Logging モード。読み取りと書き込みの並列性を高める |
| 拡張機能 | `extensions/` フォルダに配置する Python パッケージ形式のプラグイン |
| IIFE | 即時実行関数式（Immediately Invoked Function Expression）。拡張機能 JSX でグローバル汚染を防ぐために使用する |
| `TaskFlow.registerExtension()` | 拡張機能がフロントエンドにタブ・列・フォームフィールド等を登録するための API |
| `TaskFlow.api` | 拡張機能が HTTP リクエストを行うための共通ヘルパーオブジェクト |
| Sカーブ | 計画上の累積工数と実績累積工数を時系列で重ねたグラフ。進捗の乖離を把握するために使用する |
| KPI | Key Performance Indicator。プロジェクトの健全性を示す指標値 |
| 手順書 | タスクに紐付くリッチテキスト形式のドキュメント。作業手順・注意事項・スクリーンショット等を記述する |
| Quill.js | ブラウザ上で動作するオープンソースのリッチテキストエディタライブラリ。手順書編集に使用する |
| Base64 | バイナリデータ（画像等）をテキスト形式に変換するエンコード方式。手順書内の画像を DB に保存する際に使用する |
| `task_documents` | 手順書コンテンツを格納するコアテーブル。`task_id` を主キーとし、1 タスクにつき 1 件を管理する |
